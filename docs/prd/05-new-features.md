# 新需求

## 首页重构

**需求背景**：作为综合健康应用，首页不应只展示单一模块，需要支持多模块扩展。

### 快捷按钮区

| 规格项 | 描述 |
|-------|------|
| 位置 | 首页顶部 |
| 内容 | 各健康模块的快捷入口按钮 |
| 交互 | 点击直接开始该模块的记录流程 |
| 扩展性 | 后续新增模块时，自动增加对应按钮 |

### 周报告区

| 规格项 | 描述 |
|-------|------|
| 位置 | 首页主体区域 |
| 内容 | 最近一周各模块数据的图表汇总 |
| 展示形式 | 图表（趋势图、统计图等） |
| 更新周期 | 每周更新，展示上周数据汇总 |

---

## 统计页（新增）

**需求背景**：将分散的统计信息整合到独立页面，提供更详细的数据分析。

| 规格项 | 描述 |
|-------|------|
| 入口 | 设置页 → 统计分析 |
| 内容 | 各模块的详细统计数据、长期趋势图表 |
| 时间范围 | 支持查看周/月/年维度的数据 |

---

## 多用户分享功能

**需求背景**：用户希望与好友互相查看彼此的健康记录，共同关注健康状况。

### 功能规格

| 规格项 | 描述 |
|-------|------|
| 分享模式 | **仅统计数据** — 双方只能查看对方的统计分析，不能查看详细记录 |
| 绑定方式 | 邮箱搜索 + **双向互关** — 双方都关注对方才可见 |
| 展示方式 | **独立页面** — 点击好友进入好友的统计页面（非 Tab 切换） |
| 关系类型 | 多对多 — 可以互关多个好友 |
| 商业模式 | 当前免费，后续可能作为订阅功能 |

### 用户流程

```
1. 用户 A 在设置页点击「关注好友」
2. 输入用户 B 的邮箱地址并关注
3. 用户 B 同样操作，关注用户 A
4. 双方互关后，互关列表中可以看到对方
5. 点击好友 → 进入好友的统计分析页面
```

### 界面变化

| 页面 | 变化 |
|-----|------|
| 关注好友页 | 搜索用户、互关列表、点击查看好友统计 |
| 统计页 | 支持通过参数显示好友的统计数据 |
| 设置页 | 增加「关注好友」入口 |

### 数据模型

需要新增 Supabase 表：

```sql
-- 关注关系表（单向关注）
CREATE TABLE follows (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  follower_id UUID REFERENCES auth.users(id) NOT NULL,
  following_id UUID REFERENCES auth.users(id) NOT NULL,
  created_at TIMESTAMPTZ DEFAULT now(),
  UNIQUE(follower_id, following_id)
);

-- 查询互关关系的视图
CREATE VIEW mutual_follows AS
SELECT 
  a.follower_id as user_a,
  a.following_id as user_b
FROM follows a
JOIN follows b ON a.follower_id = b.following_id 
  AND a.following_id = b.follower_id;
```

### 权限控制

- 仅当双方互关时，才能查看对方数据
- 单向关注不可见对方任何数据
- 任一方取消关注，立即失去互相访问权限
