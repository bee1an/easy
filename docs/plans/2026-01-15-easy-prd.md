## 1. 产品概述

### 1.1 产品定位

**Easy**（暂定名）是一款综合健康追踪应用，帮助用户通过记录和回顾健康数据，更好地了解自己的身体规律和状态。

**模块规划**：
| 模块 | 状态 | 说明 |
|-----|------|------|
| 排便记录 | ✅ 当前 | 首个核心模块 |
| 饮食记录 | 📋 规划中 | 后续扩展 |
| 运动记录 | 📋 规划中 | 后续扩展 |

> 架构设计需预留多模块扩展性

### 1.2 目标用户

| 阶段 | 用户群体 | 说明 |
|-----|---------|------|
| 内测阶段 | 小范围测试用户 | 验证核心功能和用户体验 |
| 正式阶段 | 关注健康的用户 | 想通过数据量化了解自己的人群 |

### 1.3 发布渠道

| 阶段 | 渠道 | 说明 |
|-----|------|------|
| 内测阶段 | SideStore 侧载 | 仅限测试用户 |
| 正式阶段 | App Store | 待定 |

### 1.4 核心价值

| 价值主张 | 说明 |
|---------|------|
| 自我了解 | 通过数据了解身体规律 |
| 简单记录 | 一键开始，快速完成 |
| 数据可视化 | 图表直观展示趋势 |
| 社交共享 | 与好友互相了解健康状况 |

## 2. 页面架构

### 2.1 新页面结构

```
/splash    - 启动页
/auth      - 登录页
/home      - 首页（快捷按钮 + 周报告）

/settings  - 设置页（模块入口 + 系统设置）
```

**定位**：数据分析报告 + 功能快捷入口

```
┌─────────────────────────────┐
│  快捷按钮区                   │
│  [排便] [饮食*] [运动*]       │  ← 点击直接开始记录
```

| 元素 | 说明 |

| 快捷按钮 | 各模块入口，点击直接开始记录（如排便计时） |

### 2.3 统计页（新增）

**入口**：设置页 → 统计

**内容**：
- 详细的数据分析和图表

```

│   └── 好友/分享
├── 账户
│   ├── 云同步状态
│   └── 退出登录
```

### 2.6 页面变更对比

| 原结构 | 新结构 | 说明 |
|-------|-------|------|
| 首页：统计卡片 + 日历 | 首页：快捷按钮 + 周报告 | 首页聚焦快速操作和整体概览 |

## 5. 新需求

### 5.1 首页重构

**需求背景**：作为综合健康应用，首页不应只展示单一模块，需要支持多模块扩展。

#### 5.1.1 快捷按钮区

| 规格项 | 描述 |
|-------|------|
| 位置 | 首页顶部 |
| 内容 | 各健康模块的快捷入口按钮 |
| 交互 | 点击直接开始该模块的记录流程 |
| 扩展性 | 后续新增模块时，自动增加对应按钮 |

#### 5.1.2 周报告区

| 规格项 | 描述 |
|-------|------|
| 位置 | 首页主体区域 |
| 内容 | 最近一周各模块数据的图表汇总 |
| 展示形式 | 图表（趋势图、统计图等） |
| 更新周期 | 每周更新，展示上周数据汇总 |

### 5.2 统计页（新增）

**需求背景**：将分散的统计信息整合到独立页面，提供更详细的数据分析。

| 规格项 | 描述 |
|-------|------|
| 入口 | 设置页 → 统计分析 |
| 内容 | 各模块的详细统计数据、长期趋势图表 |
| 时间范围 | 支持查看周/月/年维度的数据 |

### 5.3 多用户分享功能

**需求背景**：用户希望与好友互相查看彼此的健康记录，共同关注健康状况。

#### 5.3.1 功能规格

| 规格项 | 描述 |
|-------|------|
| 分享模式 | 完全透明互看 — 双方可看到对方所有记录 |
| 绑定方式 | 邮箱搜索 + **双向互关** — 双方都关注对方才可见 |
| 展示方式 | 分开展示 — 通过 Tab 切换查看自己/好友的记录 |
| 关系类型 | 一对一 — 仅支持两人互绑 |
| 商业模式 | 当前免费，后续可能作为订阅功能 |

#### 5.3.2 用户流程

```
1. 用户 A 在设置页点击「关注好友」
2. 输入用户 B 的邮箱地址
3. 系统记录 A 关注了 B
4. 用户 B 同样操作，关注用户 A
5. 双方互关后，可在首页切换查看对方数据
```

#### 5.3.3 界面变化

| 页面 | 变化 |
|-----|------|
| 首页 | 增加 Tab 切换：「我的」/「TA的」（仅互关后显示） |
| 模块详情页 | Tab 切换后显示对应人的数据 |
| 统计页 | Tab 切换后显示对应人的统计 |
| 设置页 | 增加「好友」区域：关注状态、互关状态、解除关注 |

#### 5.3.4 数据模型变化

需要新增 Supabase 表：

```sql
-- 关注关系表（单向关注）
CREATE TABLE follows (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  follower_id UUID REFERENCES auth.users(id) NOT NULL,
  following_id UUID REFERENCES auth.users(id) NOT NULL,
  created_at TIMESTAMPTZ DEFAULT now(),
  UNIQUE(follower_id, following_id)
);

-- 查询互关关系的视图
CREATE VIEW mutual_follows AS
SELECT 
  a.follower_id as user_a,
  a.following_id as user_b
FROM follows a
JOIN follows b ON a.follower_id = b.following_id 
  AND a.following_id = b.follower_id;
```

#### 5.3.5 权限控制

- 仅当双方互关时，才能查看对方数据
- 单向关注不可见对方任何数据
- 任一方取消关注，立即失去互相访问权限

### 8.2 架构扩展性考虑

为支持后续饮食、运动等模块，建议：

1. **数据模型**：采用通用的 `HealthRecord` 基类 + 各模块子类
2. **UI 组件**：抽象通用的卡片、列表、统计组件
3. **路由结构**：按模块组织，如 `/poop/*`, `/diet/*`, `/exercise/*`
4. **Provider**：每个模块独立 Provider，共享用户/认证状态
5. **首页设计**：快捷按钮和周报告自动适配新增模块
