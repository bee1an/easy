## 架构扩展性考虑

为支持后续饮食、运动等模块，建议：

1. **数据模型**：采用通用的 `HealthRecord` 基类 + 各模块子类
2. **UI 组件**：抽象通用的卡片、列表、统计组件
3. **路由结构**：按模块组织，如 `/poop/*`, `/diet/*`, `/exercise/*`
4. **Provider**：每个模块独立 Provider，共享用户/认证状态
5. **首页设计**：快捷按钮和周报告自动适配新增模块
